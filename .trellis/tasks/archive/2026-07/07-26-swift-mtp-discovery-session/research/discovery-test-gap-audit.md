# Research: Discovery / Session Test Gap Audit

- Query: 审查当前 `SwiftMTPTests/MTP` 与对应 Core / Transport / Backend 实现，构造 discovery/session 子任务验收覆盖表，聚焦正常、多设备、unsupported、permission/busy/no-device、claim/alt-setting 清理、submit failure、cancel race、callback-after-cancel、split/short/ZLP、wrong transaction/response order、shutdown。
- Scope: internal
- Date: 2026-07-27

## Findings

### Baseline and acceptance contract

- 任务要求覆盖 libusb 生命周期、接口枚举、session/transaction、设备与存储 scan（`.trellis/tasks/07-26-swift-mtp-discovery-session/prd.md:5-9`）。
- Blocking AC 明确要求 claim busy/no-device/permission、unexpected container、typed mapping、Swift scan 的无/单/多设备与单 storage 失败、两个 scripted 设备路由（`.trellis/tasks/07-26-swift-mtp-discovery-session/prd.md:34-43`）。
- 设计要求 shutdown 先拒绝新提交，再 cancel active transfer，并等待 terminal callback 后退出 context（`.trellis/tasks/07-26-swift-mtp-discovery-session/design.md:23-25`）。
- 设计要求 Swift scan 顺序检查候选设备，形成含精确 `MTPDeviceID` 的 snapshot；设备/存储失败应结构化且不能破坏已解码身份（`.trellis/tasks/07-26-swift-mtp-discovery-session/design.md:14-21,42-46`）。

### Priority gaps

1. **P0 — Swift scan/backend acceptance surface is absent.** There is no `SwiftMTPBackend` implementation/test, so no-device/single/multi-device scan, typed snapshot mapping, storage failure diagnostics, inspection cleanup and exact physical-device routing cannot pass (`design.md:14-21,42-46`; `implement.md:15-18`).
2. **P0 — failed OpenSession may be reusable.** `open()` only marks `.invalid` for non-OK response branches; a thrown USB/protocol/decode error from `transact` leaves `.idle` and permits another `open()` on the same instance (`MTPDeviceSession.swift:37-79`). Add a regression before implementation changes.
3. **P1 — unexpected/response-order guards are implementation-only.** The parser contains the correct-looking guards (`MTPDeviceSession.swift:189-231`), but the required unexpected-container and order tests are absent.
4. **P1 — submit and alternate-setting failure cleanup are untested.** Both branches own manual lifetime/reverse-cleanup responsibilities (`LibUSBTransfer.swift:72-100`; `LibUSBDeviceHandle.swift:71-90`).
5. **P1 — shutdown/cancel tests are deterministic happy interleavings.** They prove callback-before-free, but not true cancel/completion races, new-submit rejection, multiple transfers or the enabled event-loop path.

### Code patterns

- C/libusb calls are injected through `LibUSBFunctionTable`, enabling exact error and ordering tests (`SwiftMTP/Services/MTP/Transport/LibUSBFunctionTable.swift:10-47,49-164`).
- `LibUSBDeviceHandle` uses idempotent lock-backed close and reverse cleanup after successful claim (`SwiftMTP/Services/MTP/Transport/LibUSBDeviceHandle.swift:29-36,88-109`).
- `LibUSBTransfer` registers with the shared context before allocation/submission and unregisters in all deferred cleanup paths (`SwiftMTP/Services/MTP/Transport/LibUSBTransfer.swift:38-100`).
- Transfer callback retains a callback box once and consumes it with `takeRetainedValue`; terminal result is guarded against duplicates (`LibUSBTransfer.swift:135-168,171-189`).
- `LibUSBContext.shutdown` marks shutdown, snapshots/cancels active transfers, waits for unregister, joins the event queue, then exits libusb (`SwiftMTP/Services/MTP/Transport/LibUSBContext.swift:39-65`).
- `MTPDeviceSession` serializes all state/transactions with one lock and invalidates opened sessions on `execute` errors (`SwiftMTP/Services/MTP/Backend/MTPDeviceSession.swift:135-168`).
